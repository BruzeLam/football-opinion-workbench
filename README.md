# 开球 · 足球观点工作台

> 把一场比赛，变成一个有事实、有冲突、有节奏、能直接录制的中文足球观点内容包。

[在线体验](https://football-opinion-workbench.vercel.app) · [查看源码](https://github.com/BruzeLam/football-opinion-workbench)

![开球 · 足球观点工作台](./public/og.jpg)

## 产品定位

「开球」是一款面向足球博主、短视频编导和体育内容团队的口播文案生产工作台。

它解决的不是“把比赛结果重新说一遍”，而是内容生产中更难的部分：

- 从大量比赛信息中找到真正值得讲的矛盾；
- 区分事实、统计、赛后回应与编辑判断；
- 把战术分析转译成普通观众能听懂的语言；
- 形成有开场、有证据、有反方观点、有结论的完整论证；
- 同时产出口播稿、剪辑时间轴、事实卡和传播标题。

一句话概括：

> 输入模糊比赛信息与创作立场，输出经过事实约束的中文足球观点内容包。

## 目标用户

### 足球短视频博主

需要在比赛结束后快速形成观点，并拿到可以直接录制和剪辑的脚本。

### 体育内容编辑与编导

需要统一事实底座、选题角度和内容结构，减少资料整理与反复改稿的时间。

### 足球社区和媒体产品

需要探索从赛程、赛果与新闻资料到观点内容的半自动生产流程。

## 核心价值

### 1. 先核验，再锐评

比分、日期、进球时间、比赛阶段等信息必须来自可追溯来源。无法确认的信息不会为了增强戏剧性而自动补写。

页面当前展示的旗舰样片使用 FIFA 官方赛报、官方赛程以及 Sky Sports 比赛报道作为事实依据。

### 2. 观点不是情绪，而是论证

每一期内容围绕一个能够被反驳的核心判断展开，并包含：

1. 冷开场：直接抛出矛盾；
2. 事实底座：说明论点依赖的关键事件；
3. 战术或结构问题：解释比赛为什么会这样发展；
4. 人员与临场选择：连接教练决定和场上结果；
5. 最强反方观点：承认另一种解释中合理的部分；
6. 最终判断：用证据回答争议；
7. 收尾金句：留下可传播的结论。

### 3. 为口播与剪辑而写

文案不是普通长文章。短句、长句、数据和判断会交替出现，并同时生成画面建议和时间码，方便录制与后期剪辑。

### 4. 强风格，但保持原创

产品吸收的是强观点足球节目的通用创作方法：节奏快、立场明确、对比强、有足球梗、敢于处理争议。

它不会声称内容由任何真实博主创作，也不会直接复刻特定创作者可识别的口头禅、长段原话或高度近似措辞。幽默主要指向战术选择、比赛矛盾和场上表现，而不是进行人身羞辱。

## 产品工作流

```text
输入比赛 / 球队 / 模糊描述
          ↓
解析球队、日期、赛事和比赛阶段
          ↓
召回候选比赛并展示匹配理由
          ↓
确认事实来源与内容边界
          ↓
提炼核心矛盾与编辑立场
          ↓
生成口播稿、时间轴、事实卡和标题
          ↓
在线编辑、改写、删除与复制
```

## 当前 MVP 能做什么

- 支持“2026.7.15 英格兰 vs 阿根廷”等明确输入；
- 支持“世界杯决赛”“昨晚阿根廷那场”等模糊描述；
- 根据球队、日期、赛事和阶段计算候选匹配度；
- 在实时赛事服务不可用时返回已核验的世界杯候选；
- 提供资料锐评、录像复盘和混合生产三种工作模式；
- 提供 60 秒、90 秒和约 3 分钟的内容版本；
- 支持克制、犀利和高强度三档表达锐度；
- 输出核心观点、论证卡、口播稿、画面时间轴、事实卡和标题；
- 显示旗舰样片、AI 初稿或演示数据，避免混淆内容性质；
- 支持在线编辑、段落改写、删除、字数统计和全文复制；
- 提供“为什么这样写”，展示内容背后的编辑策略；
- 为关键事实提供可点击的来源链接。

## 旗舰 Demo：英格兰 vs 阿根廷

旗舰样片选择 2026 世界杯半决赛英格兰 1–2 阿根廷。

这一期没有停留在“英格兰过于保守”的表面结论，而是建立了一条完整的比赛因果链：

```text
原有进攻方案奏效
      ↓
领先后转为 5-4-1
      ↓
前场接应与反击出口消失
      ↓
解围无法转化为控球
      ↓
阿根廷连续回收二点并重新组织
      ↓
警报反复出现，最终完成逆转
```

核心观点是：

> 英格兰输掉的不只是最后七分钟，而是领先后继续控制比赛的勇气与结构。

这个 Demo 同时展示了产品希望达到的内容标准：事实可以回溯、观点可以争论、因果能够解释、语言适合口播。

## 信息源与事实边界

当前 MVP 的比赛匹配由两部分组成：

- TheSportsDB：用于查询球队近期和未来赛程；
- 已核验的 FIFA 世界杯赛程索引：用于增强世界杯赛事、年份与阶段的模糊召回。

旗舰样片还引用：

- [FIFA 官方比赛报道](https://www.fifa.com/en/articles/england-argentina-match-report-highlights)
- [FIFA 世界杯官方赛程](https://www.fifa.com/en/tournaments/mens/worldcup/canadamexicousa2026/articles/match-schedule-fixtures-results-teams-stadiums)
- [Sky Sports 比赛报道与统计](https://www.skysports.com/football/england-vs-argentina/549867)

内容被划分为三类：

| 类型 | 使用方式 |
| --- | --- |
| 已确认事实 | 可以直接陈述，并尽量附带来源 |
| 编辑判断 | 明确作为分析和观点表达 |
| 未确认信息 | 省略、提示用户补充，或明确标注不确定 |

当前 MVP 不会自动观看完整比赛录像。所谓“录像复盘”代表产品工作流预留的模式；在没有视频理解能力或人工观察记录时，不会假装完成了逐帧分析。

## 产品形态

「开球」不是单独的一段 Prompt，而是三个层次组成的产品原型：

1. **观点生产方法**：负责事实核验、矛盾提炼、论证结构与原创表达；
2. **内容工作台**：负责比赛输入、候选确认、参数设置、生成与编辑；
3. **可交付内容包**：负责连接口播、剪辑、审核和多平台发布。

## 技术实现

- Next.js 16
- React 19
- TypeScript
- TheSportsDB API
- Vercel

当前生成逻辑主要用于展示完整产品工作流和旗舰样片效果。接入正式的大语言模型、检索服务或内部内容系统后，可以将模板生成替换为基于事实包的动态观点生成。

## 本地运行

需要 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。


## 产品原则

- 事实优先于情绪；
- 观点必须能够被证据支撑；
- 锐评针对足球问题，不依赖人身攻击；
- 不把推测包装成事实；
- 不冒充任何真实创作者；
- 内容最终由创作者确认和负责。
